# Maps — Mapbox + Google

PlotBoard uses **two** map providers, each doing the job it is best at. This
document covers why, what it costs, and how to set up the keys.

## The split

| Surface | Provider | Why |
| --- | --- | --- |
| Listing cards (home) | **Mapbox Static Images**, cached in R2 | A picture, not a map — costs nothing on repeat views |
| Map View tab | **Mapbox** Satellite Streets | Cheap, 50k free loads, unlimited panning |
| Listing detail map | **Mapbox**, lazy-loaded | Only loads if the viewer opens the map slide |
| Placing a pin | **Google Maps + Places** | Its Indian address/POI search is materially better |
| Pin → locality name | **Google Geocoding** | Returns the colony ("Gudhiyari"), which is how brokers describe a plot |

**Coordinates are provider-neutral.** Both use WGS84, so a pin placed in
Google renders on the identical spot in Mapbox — no conversion, no syncing,
and your stored data isn't tied to either vendor.

### Why cards must never mount a live map

Every listing card used to create its own Leaflet map. That was free on
OpenStreetMap, but on any metered provider a 15-card board is **15 billable
map loads per view** — roughly **$500/month** at 20 brokers' usage. Cards now
render a cached image instead, so browsing the board is free no matter how
often it is opened.

## Cost

All figures are for **all 20 users combined**.

| Provider | Expected use | Free tier | Overage |
| --- | --- | --- | --- |
| Mapbox map loads | ~14,000/mo | 50,000/mo | $5 / 1,000 |
| Mapbox static images | ~100/mo (one per listing) | 50,000/mo | $1 / 1,000 |
| Google map loads | ~200/mo | 10,000/mo | $7 / 1,000 |
| Google geocoding (pin → locality) | ~200/mo | 10,000/mo | $5 / 1,000 |

**Expected bill: ₹0/month**, with ~3.6× headroom on Mapbox and ~50× on Google.

A [Mapbox map load includes unlimited tile requests](https://docs.mapbox.com/accounts/guides/pricing/),
so panning and zooming inside an open map are free — only the *number of maps
opened* is metered.

**The one exposure** is the listing detail map. If brokers open listings far
more than assumed, that row alone could push Mapbox past 50,000. Mitigation is
already scaffolded: swap the detail slide for the cached static image behind a
"view interactive map" tap. **Check the Mapbox dashboard after week one — if
you're trending past ~35,000/month, apply it.**

## Setup

### 1. Mapbox

1. Sign up at [mapbox.com](https://account.mapbox.com/auth/signup/).
2. Go to **Account → Tokens**. Copy the **Default public token** (`pk.…`).
3. **Restrict it** — click the token → *URL restrictions* → add:
   - `http://localhost:5173/*`
   - `https://YOUR-APP.vercel.app/*`
4. Add to `.env.local` **and** Vercel → Environment Variables:
   ```
   VITE_MAPBOX_TOKEN=pk.your_token_here
   ```

### 2. Google Maps

1. Open [Google Cloud Console](https://console.cloud.google.com/) → create a
   project (e.g. `plotboard`).
2. **APIs & Services → Library** → enable these three:
   - **Maps JavaScript API** — the map itself
   - **Places API** — address search when finding a plot
   - **Geocoding API** — turns the dropped pin into a locality name
     ("Gudhiyari", "Shankar Nagar"). Without it the pin still works but the
     address fields stay blank, and the browser console shows
     `REQUEST_DENIED: The webpage is not allowed to use the geocoder`.
3. **APIs & Services → Credentials** → *Create credentials → API key*.
4. **Restrict the key** — this is mandatory, not optional. An unrestricted key
   that leaks can be used by anyone at your expense:
   - *Application restrictions* → **HTTP referrers**, add
     `http://localhost:5173/*` and `https://YOUR-APP.vercel.app/*`
   - *API restrictions* → **Restrict key** → select only the three APIs above
5. **Billing** must be enabled on the project even to use the free tier. Set a
   budget alert: **Billing → Budgets & alerts** → e.g. alert at $5.
6. Add to `.env.local` and Vercel:
   ```
   VITE_GOOGLE_MAPS_KEY=your_key_here
   ```

### 3. Static card thumbnails (optional, needs R2)

Cached satellite thumbnails are generated by the `media` Edge Function and
stored in R2, so this activates once [R2 is configured](STORAGE.md).

**This needs a SECOND Mapbox token — not the browser one.** Mapbox enforces URL
restrictions using the request's `Referer` header, and a server-side `fetch`
sends none, so a restricted token returns
[`403: Forbidden`](https://docs.mapbox.com/accounts/guides/tokens/) for every
request the Edge Function makes. The browser token must stay restricted, so the
server needs its own.

Create it at **Account → Tokens → Create a token**:
- Name it something like `plotboard-server-static`
- Keep the **default public scopes** (`styles:tiles` is what Static Images needs)
- Leave **URL restrictions empty**

Add it as an Edge Function secret:

```
MAPBOX_TOKEN = pk.your_SERVER_token_here
```

Because it has no URL restrictions, this token **is** a secret: anyone who
obtains it can spend your Mapbox quota. It lives only in the Edge Function's
environment and must never appear in a `VITE_*` variable or the bundle. That is
the one real difference between the two tokens — same type, opposite handling.

Until then, listings without photos show a placeholder icon — no map loads,
no cost.

## Without keys

The app is fully usable with no map keys at all: maps render as a labelled
placeholder ("Map unavailable — VITE_MAPBOX_TOKEN is not set"), and the pin
picker still accepts pasted coordinates or a Google Maps URL via
`parseCoords`. Nothing crashes and no console errors are produced.

## Security note

Both keys are **public browser keys** — they are visible in the bundle by
design. Their security comes entirely from the **domain restrictions** in step
1.3 and 2.4. The only genuinely secret map credential is the Mapbox token used
server-side for static images, which lives in the Edge Function's secrets.
